# 태그 랭킹 하루 판정 수치 재설계

- 작성: 2026-10-06
- 상태: 초안 — 사용자 검토 대기
- 관련 측정: `scratchpad/tagpanel/`(설계 패널 스크립트, git 제외) — 아래 수치는 최근 14일(2026-09-22~10-05) 데일리 실측

## 1. 왜

태그 랭킹 페이지의 수치를 여러 번 바꿨지만 각 값이 무엇을 보여 주는지 분명하지 않았다. 의도(사용자)는 그대로 두고, 계산이
그 의도를 실제로 보여 주게 다시 정한다.

| 값 | 의도(사용자) | 지금 계산의 문제(실측) |
|---|---|---|
| 작품 수 | 오늘 인기작 사이에서 얼마나 흔한가 | 없음 |
| 상위권 집중도 | 이 태그가 상위권에서 자주 쓰이는가 | (100위 안 비율) ÷ (101~500위 비율) 배수. 집중도가 있는 102개 중 55개가 100위 안 2편 이하라 한두 편에 값이 튄다 |
| 인기 점수 | 작품 수와 순위를 적절히 섞은 대표 수치 | Σ 1/ln(순위+1) — 500위가 1위의 11%로 가중이 평평해 작품 수와 상관 0.9986. 사실상 작품 수 |
| 구역 4개 | 대세 · 적게 쓰이지만 성적 좋은 태그 · 너무 많은 태그 · 시들어 가는 태그 | 경계(그날 P75 · 집중도 1.0)가 날마다 흔들려 하루 8.3개가 구역을 바꾼다. '오늘 약세'는 하루 자료로 말할 수 없는 '시들어 감'을 이름에 담았다 |
| 지형 지도 | 위 값들로 태그를 눈으로 비교 | 197행 표 아래(약 1만 px)에 묻혀 거의 보이지 않는다 |

## 2. 원칙

- **랭킹 페이지는 그날 하루의 데이터로만 판단한다.** 흐름(시들어 감, 떠오름)은 기간 페이지(태그 트렌드)가 맡는다.
- 값마다 방문자에게 **한 문장**으로 설명된다. 비율의 비율 같은 변환을 화면에 내지 않는다.
- 임의 가중치보다 **노벨피아가 매긴 값**(랭킹 점수)을 그대로 쓴다.
- '상위권'은 상위 500편 안에서 다시 꼭대기(100위 안)를 뜻한다 — 500편 밖의 태그 분포는 모으지 않아 플랫폼 전체와는 비교할 수 없다.

## 3. 값

N = 그날 순위가 매겨진 작품 수(데일리 500). p0 = 100/N = 평균 100위 안 비율(데일리 20%).

| 값 | 계산 | 화면 설명(한 문장) |
|---|---|---|
| 작품 수 n | 그날 N편 중 이 태그를 단 작품 수. 2편 미만은 적재 때 제외(지금 그대로, 노이즈 제거) | 오늘 인기작 500편 가운데 이 태그를 단 작품 수입니다. |
| 100위 안 t · 비율 | t = 100위 안 작품 수, 비율 = t/n. 화면은 "7편 · 32%" | 이 태그 작품 중 100위 안에 든 작품과 그 비율입니다. 평균은 20%(5편 중 1편)입니다. |
| 인기 점수 | Σ(이 태그 작품의 랭킹 점수) ÷ Σ(그날 N편 전체 랭킹 점수), % 로 표시 | 오늘 인기작 500편이 받은 랭킹 점수 가운데 이 태그 작품들이 차지하는 몫입니다. |

- **인기 점수가 순위를 반영하는 방식:** 랭킹 점수는 순위에 따라 가파르게 떨어진다(10/06: 1위 441,600 · 100위 42,600 · 500위 7,700 —
  상위 100편이 전체의 56%). 이 차이가 그대로 들어간다. 14일 실측: 작품 수 순서와의 순위 상관 0.800(지금 0.974), 날마다 순위 안정성
  평균 0.9976. '100위마다 절반' 가중치(0.801 · 0.9980)와 결과는 거의 같지만 지어낸 숫자가 없다.
- **표의 순서 = 인기 점수 순.** 동점은 태그 이름 순(지금 데일리는 동점 순서가 날마다 바뀌어 가짜 변동이 생겼다).
- **변동 = 인기 점수 순위의 전날(달력 −1일, 데일리 규칙) 대비.**
- 상위권 집중도 배수('1.23배')는 이 페이지에서 쓰지 않는다. 기간 페이지의 기간 집중도는 이 문서 범위 밖이다.

## 4. 구역 — 3개, '오늘 약세'는 없앤다

흔한 태그 기준선 cut = ceil(0.06 · N) — 데일리 30편. 그날 분포(P75)가 아니라 N 에 대한 고정 비율이라 날마다 움직이지 않는다.

| 구역 | 조건 | 뜻(화면) | 10/05 예(작품 수 / 100위 안 / 비율) |
|---|---|---|---|
| 대세 | n ≥ cut, 비율 ≥ p0 | 많이 쓰이면서 100위 안에도 평균 이상 들어간 태그 | 판타지 293/69/24% · 하렘 275/60/22% · 집착 149/37/25% · 착각 · 먼치킨 |
| 과포화 | n ≥ cut, 비율 < p0 | 많이 쓰이지만 100위 안에는 평균보다 덜 들어간 태그 | 현대판타지 229/44/19% · 현대 203/35/17% · TS 130/18/14% · 일상 · 라이트노벨 |
| 숨은 강자 | 5 ≤ n < cut, t ≥ 4, 비율 ≥ 1.5·p0(30%) | 적게 쓰이지만 100위 안에 4편 이상, 평균의 1.5배 넘게 들어간 태그 | 이세계 16/7/44% · 괴이 19/7/37% · 노맨스 · 괴담 · 게임 |
| (없음) | 그 밖 | 표시하지 않는다 | 약 80%(대부분 원래 마이너한 태그) |

- **경계 표시:** n ≥ cut 이고 |비율 − p0| ≤ 2%p 이면 구역 옆에 '경계'를 단다. 하루 구역 바뀜 1.9개 중 약 1.5개가 여기서 나온다 —
  규칙은 그대로 두고 흔들릴 수 있다는 것만 알린다(완충 구간은 실측에서 바뀜이 오히려 늘어 버렸다).
- **숨은 강자의 t ≥ 4:** 왼쪽 위에 있어도 100위 안 3편 이하는 우연과 구별하기 어려워 구역을 붙이지 않는다(툴팁: "100위 안 3편 — 판단 보류").
- 시들어 가는지는 태그 트렌드(기간)에서 본다 — 지도 아래 안내 한 줄.
- **14일 실측:** 하루 구역 바뀜 8.3개 → 1.9개. 다음 날 같은 구역 유지 대세 96% · 숨은 강자 99% · 과포화 93%.
  10/05 개수 대세 15 · 숨은 강자 10 · 과포화 11(지금은 대세 15 · 숨은 강자 33 · 과포화 11 · 약세 43).

## 5. 화면

순서: 제목 줄 → 구역 칩 3개 → 지형 지도 → 표(상위 50 + 전체 보기) → 각주.

**구역 칩.** 대세 · 숨은 강자 · 과포화 — 태그 수와 대표 3개. 누르면 지도와 표가 함께 걸러진다(기존 구역 필터 줄 대체).

**지형 지도(표 위).**
- 가로 = 작품 수(로그), cut(30편)에 세로선. 세로 = 100위 안 비율 0~60% 고정, p0(20%)에 '평균' 가로선. 60% 넘는 점(14일 1,378점 중 4개)은 ▲로 끝에 붙인다.
- 칸은 넷이지만 구역은 셋이다. 오른쪽 위 = 대세, 오른쪽 아래 = 과포화, 왼쪽 위의 숨은 강자 영역(비율 30% 이상)만 옅게 칠한다.
  **왼쪽 아래와 숨은 강자 영역 밖은 이름 없는 바탕**(회색 점, 칸 이름 없음, 칩 없음 — 사용자 결정 A).
- 원 크기는 없앤다 — 인기 점수가 가로축(작품 수)과 거의 같은 정보다. 점은 같은 크기, 색 = 구역.
- 이름표는 기존 충돌 회피 배치를 쓰되 대세·숨은 강자·과포화 점을 먼저, 회색 점은 마우스를 올릴 때만.
- 툴팁: "작품 N편 · 100위 안 t편(x%) · 인기 점수 y%".
- 표 행에 마우스를 올리면 점이 강조되고, 점을 누르면 그 태그를 표에서 찾는다(기존 onHover/onPick).
- 지도 아래 한 줄: "작품 5편 미만 태그는 그리지 않습니다 · 시들어 가는 태그는 태그 트렌드에서".
- 데스크톱 높이 약 380px. 폰(<768px)은 칩이 요약을 맡고 지도는 '지도 보기'로 접어 둔다.

**표 열.** 순위 · 변동 · 태그(구역 점 · '경계') · 인기 점수(%) · 작품 수 · 100위 안("7편 · 32%"). 인기 점수·작품 수·100위 안 비율로 정렬.
폰 행: 태그 / 구역 · 인기 점수 · 작품 · 100위 안 한 줄.

**각주.** 세 값의 한 문장 정의와 구역 규칙(한 줄씩). 지금의 지도 제목 아래 해설 문장은 없앤다.

## 6. 데이터 흐름

**적재(파이프라인 — main 에서 딴 짧은 브랜치).**
- `data-pipeline/data_ingestion.py` `calculate_and_store_tag_trends`: STATS 에 `TagScoreSum`(태그별 Σ 랭킹 점수)·`ScoreTotal`(N편 전체 Σ)·
  `RankedTotal`(N)을 더한다. 기존 필드(TagCounts·TagCountsTop100·TagWeightedScoresLogarithmic)는 그대로 둔다(기간 페이지가 쓴다).
- 과거 STATS 소급: `scripts/backfill_tag_score_sum.py` — 날짜별 소설 항목(Ranking·Score·Tags)에서 세 필드만 `update_item`. `--dry-run` 먼저.
  **배포 전에 소급이 끝나야 한다** — 아니면 변동·14일 순위선이 두 정의를 섞는다. 상세를 못 읽은 자리표시 행도 랭킹 점수는 순위 목록에서 오므로 그대로 들어간다(태그가 없으면 어느 태그에도 더해지지 않고 ScoreTotal 에만 든다).
- 2026 공모전: `consolidate_contest_data.daily_tag_stats` 에 같은 뜻의 `TagScoreSum`(Σ 그날 조회 증가 `ViewDelta`)·`ScoreTotal` 을 더한다
  (공모전 일간 순위의 기준이 조회 증가). 지난 날짜는 같은 소급 스크립트의 공모전 모드로 채운다. 배포는 `deploy.sh code`.

**백엔드(`main.py`, 웹 브랜치 — 사용자가 배포).**
- `/api/ranks/tags/{date}`: 응답에 `count`·`top100`·`ranked_total`·`score_share` 를 싣고 순서를 `score_share` 로. 전날 비교 변동도 같은 값으로.
- 14일 이력(`/api/trends/tags/series`)의 순위도 `score_share` 기준. 지난 날짜에 새 필드가 없으면(소급 전) 기존 점수로 떨어지지 않고 그 날을 비운다.
- `_tag_stats_without_blocked`: 뺄셈에 `TagScoreSum`·`ScoreTotal` 을 넣는다 — 작품 단위 단순 합이라 그대로 성립. 가벼운 조회 투영에 `Score` 를 더한다.
- `_contest_daily_tag_ranking`: 같은 꼴. 2025 공모전(구 3-track)은 그대로.

**프론트(웹 브랜치).**
- `utils/tagZones.ts`: 구역 3개, cut = ceil(0.06·N), 경계 표시 판정. `tagZones.test.ts` 경계 사례(n=30 · 20% → 대세, 19% → 과포화, 22% → 경계,
  n=16 · t=4 · 30% → 숨은 강자, t=3 → 없음, n=4 → 없음).
- `TagTerrainMap.tsx`: 축·영역·점 크기·▲ 처리 교체. `DailyTagBoard.tsx`: 칩 · 지도 위로 · 열. 공모전 판도 같은 컴포넌트를 쓴다.

## 7. 2026 공모전 판

같은 정의를 N 비례로 쓴다(p0 = 100/N, cut = 6%·N, 숨은 강자 = 1.5·p0 · t ≥ 4). 다만 공모전은 N 이 약 2,700~3,000 이라 p0 가 3.7% 안팎이고
흔한 태그 기준이 160편 이상이 된다 — **데일리 14일로만 정한 기준이라, 공모전 일간 데이터(10/01~)로 같은 측정을 먼저 하고** 맞지 않으면
공모전용 상수를 따로 둔다(구현 계획의 첫 단계).

## 9. 위험과 약점

1. 인기 점수는 여전히 작품 수를 많이 따른다(피어슨 0.99). 합산 점수인 이상 피할 수 없고, 순위의 영향은 중간 순위대에서 보인다.
2. 흔한 태그 중 비율이 20% 바로 옆인 태그는 대세와 과포화를 오간다 — '경계'로 드러낸다.
3. 구역 없는 태그가 약 80%가 되고, 지금 '오늘 약세' 43개의 표시가 사라진다.
4. 기준값(6% · 20% · 30% · 4편 · ±2%p)은 데일리 14일로 정했다. 공모전은 7절대로 다시 잰다.
5. 소급이 배포보다 먼저여야 한다(6절).
