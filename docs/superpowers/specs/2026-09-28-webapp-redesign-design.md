# NovelFlow 웹앱 개편 설계

- 날짜: 2026-09-28
- 브랜치: `feat/webapp-redesign`
- 시안(로컬 전용, git 제외): `.design-concepts/4차-A-vs-C/` — `table.html`(일간 랭킹, `?dark`로 다크), `A.html#detail`(작품 상세), `tag.html`, `tagtrend.html`, `report2.html`(분석), `filter.html`(필터 배치 비교). 모두 2026-08-28 ~ 09-27 실제 수집 데이터로 그렸다.

## 1. 목표

**모든 페이지는 웹소설 독자·작가를 위한 것이다.** 데이터 엔지니어링 고민은 화면이 아니라 GitHub(README, `docs/`)에 기록한다.

지금 디자인(2026-08-29 "클린 모던")의 기능은 모두 유지하고, "AI가 만든 것처럼 보이는" 패턴을 없앤다. 방향은 멜론·네이버 시리즈·빌보드 같은 **차트 페이지** 문법이다.

### 성공 기준

- 카드 격자, 알약 칩, 헤딩 아래 부제·설명 문구, 큰 숫자 타일, 영문 눈썹 라벨이 **어느 페이지에도 없다**.
- 숫자가 Inter 글꼴로 보이지 않는다(Pretendard 제거).
- 지금 되는 기능이 전부 된다(§10 체크리스트).
- 라이트·다크 두 테마, 360~1440px에서 깨지지 않고 가로 스크롤이 없다.

### 범위 밖 (별도 하위 프로젝트)

| 항목 | 이유 |
|---|---|
| 분석 페이지 **LLM 구간 요약 생성기** | 하루 1회 7/30/90일 요약을 Claude API로 만들어 `AISUMMARY#<days>`에 쓰는 파이프라인. 이번 개편은 화면의 자리만 만든다(요약이 없으면 자리를 숨김). |
| **인생픽 순위** 수집·소급 | 500편 중 약 7%(9/26 33편, 9/27 34편)만 순위가 공개돼 표 열로는 쓰지 않는다. 작품 상세에 "있을 때만" 보이게 하려면 파서 추가 + `reparse_raw.py`로 9/5 이후 소급이 필요. |
| 수집 기록을 운영 기록 페이지로 확장 | 사용자용 페이지로 유지하기로 함. |

## 2. 접근

**토큰을 먼저 바꾸고, 페이지를 하나씩 재구성한다.** 첫 단계에서 서체·색·모서리를 전 페이지에 적용하고, 이후 페이지 단위로 구조를 바꾼다. 페이지마다 확인·커밋할 수 있고 중간 상태에서도 사이트가 깨지지 않는다.

그대로 두는 것: 라우팅, API 호출, 데이터 훅, 정렬·필터 로직(고급 태그 조건식 포함), 가상 스크롤, `NovelCover`(표지 블러), 테마 전환 구조, Algolia 검색.

## 3. 디자인 시스템

### 3.1 서체

- **Wanted Sans Variable** 하나. `https://cdn.jsdelivr.net/npm/wanted-sans@1.0.3/fonts/webfonts/variable/split/WantedSansVariable.min.css` (OFL-1.1).
- 숫자는 전부 `font-feature-settings: "tnum"`.
- Pretendard 로드(`index.html`)와 두 군데의 font-family 선언(`src/index.css`, `styles/base.css`)을 없애고 `--font-sans` 토큰 하나로 둔다.
- 한글에 넓은 자간(0.1em 이상)을 쓰지 않는다. 지금 `.sidebar-label`, `.page-hero__eyebrow`, `.novel-stat-label` 등에 남아 있다.

- **상승은 빨강, 하락은 파랑**(한국 차트 관례: 멜론 `#FF2C75`/`#56A3FF`, 네이버 시리즈). 지금의 초록/빨강을 대체한다.
- 쇼케이스 띠 위 글자는 표지 위에 얹히므로 두 테마 모두 흰색으로 고정한다(2026-08-30 결정 유지).
- 바탕색을 바꿀 때는 `index.html`의 두 theme-color meta, `ThemeProvider`의 `THEME_BG_COLORS`, 토큰 세 곳을 같이 바꾼다. iOS용 theme-color는 이중 meta의 `media`를 바꿔 끼우는 방식을 유지하고, sticky 헤더에 `backdrop-filter`를 쓰지 않는다.
- 대비는 합성 후 픽셀로 잰다. 반투명 위에서 계산기 값을 믿지 않는다(기존 규칙).

### 3.3 표기 규칙

| 대상 | 표기 |
|---|---|
| 순위 변동 | `▲3` 빨강 · `▼2` 파랑 · `–` 흐림 · `NEW` 주황 |
| 숫자 열 | **오른쪽 정렬**, tabular (2026-08-30 "좌측 정렬" 결정을 대체) |
| 정렬 | 머리글을 누름. 머리글 뒤에 `↕`, 정렬 중이면 `↓`/`↑` |
| 큰 수 | 표 안에서는 정확한 값(`461,400`). 쇼케이스·한 줄 수치에서는 `785만`, `1.2억` |
| 날짜 | 제목 옆 `2026.09.27`, 문장 안 `9월 27일`, 시각은 "밤 9시" |
| 없는 값 | `–` (예: 유효 회차 30개 미만의 초반 잔류, 5작품 미만의 집중도) |
| 산식 | 표 머리글의 `title`과 표 아래 번호 각주 ①② 두 곳. 헤딩 아래에는 쓰지 않는다 |

### 3.4 금지 패턴

- 카드·패널 격자, 테두리 박스로 섹션 감싸기. 섹션 구분은 가로선 한 줄로 한다.
- 알약 칩 줄, 칩 구름. 태그는 `#판타지` 텍스트 링크로 쓴다.
- 헤딩 아래 부제·설명 문단.
- 큰 숫자 타일 줄. 수치는 `조회 72.2만 | 추천 3.6만`처럼 한 줄에 쓴다.
- 영문 눈썹 라벨, 그라데이션 버튼.
- 예외: 분석 페이지의 **LLM 요약 문단**에만 연한 바탕 면 하나를 허용한다("생성된 글"과 "수집한 숫자"를 구분하려는 목적).

## 5. 페이지별 설계

### 5.1 일간 랭킹 (`/novels/rankings/:date?`) — 시안 `table.html`

위에서 아래로:

1. `PageTitle`: `일간 랭킹 ‹ 2026.09.27 ›` / `밤 9시 · 노벨피아 7일 조회순 상위 500`
2. **쇼케이스 유지**: 상위 5작품 · 급상승 5작품. 순위 칩은 검정 반투명, 상승 칩은 빨강(`▲135`). 띠 글자는 상위가 `작가 · 점수 461,400`, 급상승이 `416위 → 281위`. 그룹 제목 옆 설명은 없앤다.
3. `TabBar`: 전체 / 급상승 / 신규 진입 + 검색칸 + `필터 N` 버튼
4. `AppliedFilters`(조건이 있을 때만)
5. `RankTable` **10열**: 순위 · 변동 · (표지 34×48) · 제목 · 작가 · 점수 · 회차 · 추천비 · 초반 잔류 · 최신 잔류 · 태그. 행 높이 60px, 1~3위 순위 숫자는 빨강.
   - **행 펼침**: 행을 누르면 그 자리에서 30일 순위선, `30일 중 24일 차트인 · 최고 4위 · 조회 722,436`, `작품 정보 보기`. 데이터는 펼칠 때 기존 트렌드 API로 가져온다.
6. **모바일**: 제목 / `작가 · 점수 · 회차` / `추천비 · 초반 · 최신` / 태그 링크 네 줄. 가로 스크롤 없음.

넣지 않기로 한 열: 누적 조회, 30일 최고(비좁음), 인생픽(대부분 비어 있음).

### 5.2 작품 상세 (`/novels/:novelId`) — 시안 `A.html#detail`

1. `‹ 일간 랭킹` 뒤로 링크
2. 머리: 표지(176px, 블러) + 제목 + `작가 · 연재 61화 · 노벨피아에서 보기` + 큰 순위 `8위 ▼1 전일 대비` + 한 줄 수치 `조회 72.2만 | 추천 3.6만 | 선호 6,981 | 추천비 4.99% | 초반 잔류 42% | 최신 잔류 47%`
3. **차트**: 지금의 지표 5개(랭킹, 점수, 조회수, 추천, 선호)를 모두 유지한다. `PeriodPicker`(7일 기본), 구간 선택 막대(Brush), 확대 보기, 2025-07-21 집계 기준 변경(300→500위) 표시선을 유지한다. 순위는 선, 하루 증가는 막대 스타일로 통일하고, 순위권 밖 날은 선을 끊는다. 지금의 "참고: …변경되었습니다" 안내 상자는 표시선 라벨로 대체한다.
4. 작품 소개(줄거리) 본문
5. 맨 아래 태그 텍스트 링크. 누르면 그 태그로 필터한 일간 랭킹으로 간다.

### 5.3 태그 랭킹 (`/tags/rankings/:date?`) — 시안 `tag.html`

지금의 다섯 겹(요약 카드 4 · 선택 패널 · 순위표 · 지도 · 구역 칩 4패널 · 변동 카드 3)을 **표 하나 + 탭 + 구역 필터 + 행 펼침 + 지도**로 줄인다. 2026-08-31의 미결("다섯 방식은 과하다, 사용자 판단")은 이것으로 닫는다.

1. `PageTitle`: `태그 랭킹 ‹ 날짜 ›` + 오른쪽 **오늘 / 기간 트렌드** 전환(태그 트렌드로 이동)
2. `TabBar`: 전체 / 뜬 태그 / 식은 태그 / 새로 진입(개수) + 태그 검색
3. 구역 필터 한 줄: `전체 198 · ● 오늘의 대세 16 · ● 숨은 강자 31 · ● 과포화 9 · ● 오늘 약세 44`
4. `RankTable` 7열: 순위 · 변동 · 태그 · 구역 · 작품 수 · 상위권 집중도① · 인기 점수② + 각주 두 줄
   - **행 펼침**: 14일 순위선, `9월 14일 45위 → 오늘 43위 · 작품 18편 · 집중도 0.2×`, `'태그' 작품 보기`(태그 → 작품 연결은 새로 생긴다)
5. **태그 지형 지도 유지**: 로그 가로축, 세로축(sqrt), 상한 8×(▲ 표시), 원 크기 = 인기 점수, P75·1.0 기준선, 4분면 이름, 지금의 라벨 충돌 회피 로직. 새 구역 색만 입힌다.

구역 판정(P75, 1.0, 5작품), 산식, 정렬 규칙, "빈 값은 항상 끝"은 모두 그대로다.

### 5.4 태그 트렌드 (`/tags/trends`) — 시안 `tagtrend.html`

1. `PageTitle`: `태그 트렌드` + `PeriodPicker`(7일 기본) + 오늘 / 기간 트렌드 전환
2. 한 줄 수치: `평균 순위 이동 8.5계단 | 순서 일치도① 0.87 | 태그 196 → 198개 | 양쪽에 다 있음 181개`
3. `TabBar` 6개: 뜬 태그 · 식은 태그 · 새로 들어옴 · 빠짐 · 치솟았다 돌아옴 · 많이 출렁임(개수)
4. 탭마다 맞는 열의 표. 예: 뜬 태그는 `시작 순위 · 끝 순위 · 변동 · 기간 최고 · 작품 수(시작→끝) · 인기 점수 변화율`, 치솟았다 돌아옴은 `시작 · 기간 최고 · 끝 · 치솟은 폭`. 행 펼침은 기간 순위선 + `작품 보기`.
5. 각주: 순서 일치도 정의, 5작품 이상 기준

목록 정의(5작품, 치솟음 3계단 이상, 출렁임 4일 이상, 정렬 기준, 기간 한 번에 가져오기)는 그대로다. 패널 밑 해명 문구 두 개는 탭 이름으로 대체한다.

### 5.5 공모전

**공통**: `우주최강 공모전 2025 ▾ ‹ 날짜 ›`(연도 텍스트 드롭다운) + 오른쪽 **작품 / 태그** 전환. 지금의 알약 내비와 탭 불일치를 없앤다. 제목 아래 `매일 오후 2시 · 참가작 4,719편`이 "집계 안내" 버튼을 대체한다.

- **공모전 랭킹**(`/contests/:year/:date?`): 일간과 같은 구조.
  - 수상작 쇼케이스(최대 11, 시상대 배치) 유지.
  - 탭: 전체 / 수상작 / 급상승 — 사이드바의 "수상작만 보기"를 대체.
  - 필터는 `FilterDrawer`.
  - 표 10열(순위 · 변동 · 수상 · 제목 · 작가 · 조회수 · 누적 조회수 · 추천비 · 회차 · 태그), 기본 정렬 조회수. 수상은 배지 대신 색 글자.
- **공모전 태그**(`/contests/:year/tags/rankings/:date?`): 태그 랭킹과 같은 표 스타일.
  - **구 3-track 점수 유지**(선형 · 역순위 · 로그, 2026-04 결정).
  - "합계 / 평균" 전환으로 열을 6개로 줄이되 값은 모두 볼 수 있게 한다.
  - 표시 범위 Top 20/50/100은 도구줄 텍스트 선택.
  - 포지셔닝 맵 유지. 지형 지도 스타일로 다시 칠하고, 10색 순위 범례는 한 색의 진하기 단계로 바꾼다. 행 호버 → 점 강조를 DOM 직접 조작 대신 상태로 옮긴다.
  - Bootstrap `Card/Row/Col`과 하드코딩 색 제거.
- **공모전 작품 상세**(`/contests/:year/novels/:novelId`): 작품 상세와 같은 구조. 제목 위 텍스트 한 줄 `우주최강 공모전 2025 · 대상`. 지금의 지표 4개(랭킹, 조회수, 추천, 선호)를 유지한다.

### 5.6 분석 (`/trends`) — 시안 `report2.html`

A 디자인을 기반으로 **그래프를 쓰지 않고** 수치를 더 보여 준다.

1. `PageTitle`: `분석` + `PeriodPicker`(7/30/90일, 기본 30일 유지)
2. **LLM 구간 요약 문단**(연한 바탕 + `요약 · 2026.09.27 밤 9시 수집분을 바탕으로 자동 생성`). 요약이 없으면 **자리를 숨긴다**. 지금처럼 "준비되지 않았습니다"를 띄우지 않는다.
3. 일곱 섹션(순서 유지). 섹션마다 `h2` + 한 줄 수치 + 표/목록 + 끝에 각주 한 줄:

| 섹션 | 내용 |
|---|---|
| 새로 들어온 작품과 빠진 작품 | 목록 두 개(순위 표시) + `많이 달린 태그 역키잡 ×3.2 …` 한 줄. 막대 없음 |
| 순위가 얼마나 움직였나 | `평균 이동 46.5계단(무작위라면 167) \| 절반은 30계단 안 \| 크게 움직인 10% 115계단+ \| 순서 유지도 0.72` + 순위대별 "첫날에도 있던 비율" 표 |
| 회차가 많이 올라온 작품 | 한 줄 수치(연재 · 주당 중앙값 · 상위 10% · 최대 · 변동 없음) + 표. 히스토그램 없음 |
| 읽은 사람 대비 추천이 많은 작품 | 좌우 목록(100위 안/밖) + 기간 조회 증가 |
| 회차를 넘겨도 독자가 남는 작품 | 표 |
| 작품 하나를 같은 순위대와 견주기 | 검색 + `지표 · 이 작품 · 순위대 중앙값 · 순위대 안 위치(상위 N%)` 표. 타일·막대 없음 |
| 함께 달리는 태그 | **두 태그 15개 · 세 태그 12개를 나란히**(§6) |

지금의 **"많이 쓰인 태그의 짝"(companions)과 "신규 작품에서만 보이는 조합" 목록은 뺀다**(확정 시안 기준). 해명 문구는 섹션 끝 각주 한 줄로 줄인다. 섹션 제목의 "500위 안"은 "랭킹 목록"으로 쓴다(2026-09-07 결정).

### 5.7 작가 (`/authors/:authorId`)

`작가명` + `작품 N편 · 총 조회 …` 한 줄 + `RankTable` 행(표지, 제목, 회차 · 조회 · 선호, 오늘 순위). 포스터 2열 격자와 카드 안 태그 칩 6개는 행 끝 텍스트 링크로 바꾼다. 빈 상태는 한 줄 문장으로 둔다.

### 5.8 수집 기록 (`/data-collection-info`)

구조를 유지한다(이미 문서형). 새 서체·색만 입히고, 고정폭 눈썹 라벨을 없애고, "매일 21시" → "밤 9시"로 바꾼다. 수치를 API에서 계산하는 규칙은 그대로다.

### 5.9 헤더·푸터·기타

- 푸터의 "공개 기간 동안 일부 등급 제한 작품은 목록에서 제외" 문구를 지운다(2026-09-27 해제). "수집 및 랭킹 기준" 링크는 유지한다.
- 검색 미설정 시의 개발자용 문구("Algolia 인증 정보를 추가해주세요")를 사용자 문구로 바꾼다.
- 알 수 없는 URL에 `*` 라우트로 "페이지를 찾을 수 없습니다" 한 줄을 보인다. 삭제된 `/trends/novels`는 `/novels/rankings`로 돌린다.

## 6. 백엔드 변경

| 항목 | 내용 |

## 8. 빈 상태·오류

- 로딩: 표 자리에 행 높이만큼의 흐린 줄(스켈레톤). 스피너만 띄우지 않는다.
- 빈 탭·빈 구역: 표 자리에 한 줄 문장(예: `이 기간에 새로 들어온 태그가 없습니다`).
- API 오류: 한 줄 문장 + `다시 시도`. 내부 메시지는 보이지 않는다(백엔드 규칙 그대로).
- 없는 값은 `–`(§3.3). `–` 하나로 "변동 없음"과 "데이터 없음"을 뭉뚱그리지 않는다(08-30 규칙). 변동 없음은 흐린 `–`, 데이터 없음은 셀 비움 또는 `순위 밖`.
